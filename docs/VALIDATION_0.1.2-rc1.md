# Проверка AIMP ETS2 Cast 0.1.2-rc1

Дата: 17 сентября 2026 года.

## Причина исправления

В реальном логе AIMP версий 0.1.0 и 0.1.1 присутствовали записи
`PCM queue busy; dropped_blocks=1`. DSP callback выбрасывал целый PCM-блок,
если encoder в тот же момент кратковременно держал блокировку очереди.

Дополнительный тест обнаружил вторую проблему: при отсутствии PCM в течение
2062 мс версия 0.1.1 закодировала только 900 мс тишины. Из-за этого буфер
listener постепенно опустошался.

## Изменения

- PCM-блок больше не отбрасывается при кратком конфликте блокировки очереди.
- После подтверждения PCM-разрыва тишина заполняет фактически прошедшее время.
- В лог добавлены длительность автоматической тишины и причина отключения
  listener.

## Результат локального теста

- Чистая x64 Release-сборка: PASS.
- CTest: 1/1 PASS.
- Start/Stop/Start: три цикла PASS.
- HTTP `200 OK` и `Content-Type: audio/mpeg`: PASS.
- Первый MP3 frame начинается с offset 0: PASS.
- VLC завершил тест без ошибок декодирования и без `PCR too late`: PASS.
- Переход 44,1 -> 48 кГц без смены endpoint: PASS.
- Искусственный PCM-разрыв: 2016 мс.
- Закодированная тишина во время разрыва: 1969 мс.
- Максимальный интервал между MP3-пакетами: 219 мс; он меньше стартового
  запаса 750 мс.
- DSP callback: 647 вызовов, среднее 11,895 мкс, максимум 1,382 мс.
- Host, HTTP probe и VLC завершились с кодом 0.

## Что ещё нужно проверить

Это предварительный релиз для тестовой группы. Рабочая установка AIMP на
машине сборки защищена ACL, а доступный интерфейс автоматизации не умеет
управлять нативным окном AIMP. Поэтому RC1 ещё нужно проверить в реальном
AIMP и ETS2. Стабильный релиз 0.1.1 и установленный DLL не заменялись.
