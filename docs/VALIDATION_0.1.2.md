# Проверка AIMP ETS2 Cast 0.1.2

Дата: 18 сентября 2026 года.

Отчёт не содержит имён пользователей, локальных путей к музыке и содержимого
пользовательских файлов.

## Окружение

- Windows 11 24H2 x64, build 26100.
- AIMP 5.40.2700 x64.
- Euro Truck Simulator 2 1.61.1.0s.
- `libLAME.dll` x64 из AIMP, LAME 3.100.
- GCC/MinGW-w64 16.2.0 из w64devkit 2.9.1.

## Сборка и автоматические проверки

- Чистая Release x64-сборка: PASS.
- CTest: 1/1 PASS.
- Экспорт `winampDSPGetHeader2` и загрузка DLL тестовым DSP-хостом: PASS.
- Несколько циклов Start → Stop → Start без перезагрузки DLL: PASS.
- HTTP `200 OK` и `Content-Type: audio/mpeg`: PASS.
- Первый MP3 frame начинается с offset 0: PASS.
- Обычный MP3-клиент: 984576 байт аудио за 30 секунд, максимальный интервал
  между блоками 32 мс, интервалов более 150 мс нет.
- ICY-клиент: 64 блока метаданных, 64 непустых, три разных названия трека в
  одном HTTP-соединении.
- Тест backpressure намеренно не читал ICY-поток 20000 мс и воспроизвёл
  `WSAEWOULDBLOCK`: данные сохранялись в ограниченной очереди до 2 МБ, после
  возобновления чтения очередь разгрузилась, listener не отключился, принято
  987516 байт.
- DSP callback: 2812 вызовов, среднее 8,830 мкс, максимум 1,277 мс.
- Переход входного PCM 44,1 → 48 кГц перезапускает только кодировщик, не
  меняя HTTP endpoint.
- Искусственный разрыв PCM около двух секунд заполнен автоматической тишиной;
  соединения слушателей сохранились.

## Старт потока

- Первый PCM-блок появился через 0 мс после Start.
- Первый валидный MP3 frame появился через 31 мс.
- Стартовый буфер был готов через 750 мс и содержал 24576 байт, то есть около
  768 мс MP3-аудио.
- Подключённым клиентам сначала передаётся готовый стартовый запас, затем
  текущий поток.

## Проверка в реальных AIMP и ETS2

- Загрузка DSP-плагина в AIMP: PASS.
- Воспроизведение `http://127.0.0.1:6969/stream` в ETS2: PASS.
- Переключение нескольких треков AIMP без потери соединения ETS2: PASS.
- Pause/Play и повторный Start/Stop: PASS.
- Обычный внешний клиент получил валидный MP3-поток без разрывов: PASS.
- Внешний ICY-клиент получил восемь разных названий треков в одном соединении:
  PASS.
- Реальный ETS2-клиент `FMODStudio/2.03.11` воспроизвёл прежнюю ошибку:
  временный Winsock `10035` ошибочно отключал listener. После добавления
  ограниченной очереди этот сценарий закрыт отдельным regression-тестом.
- Финальная повторная проверка ETS2 длилась более 90 секунд. FMOD штатно
  открыл новое соединение перед закрытием старого; плагин не зафиксировал
  `10035` или переполнение очереди `10055`. Второе соединение оставалось
  `ESTABLISHED`, encoder и HTTP-сервер не перезапускались.
- Во время этой проверки выполнено шесть переключений трека; названия в ICY
  обновились, ETS2 продолжил воспроизведение: PASS.

Станция в тестовом `live_streams.sii` называлась «Дальнобой FM». Перед
изменением файла была сделана резервная копия; остальные станции не удалялись.

## Известное ограничение ETS2

ETS2 1.61 воспроизводит поток, но не показывает ICY-название текущего трека.
Метаданные проверены отдельным совместимым клиентом. ETS2 запрашивает их через
`Icy-MetaData: 1` и корректно воспроизводит такой поток, хотя не выводит
название в интерфейсе. Клиенты без этого заголовка получают чистый MP3 без
служебных ICY-блоков.
